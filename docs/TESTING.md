# Testing

```bash
go test ./...                     # all packages
go test ./research -run Parity -v # parity with the original implementation
go run ./cmd/research check       # same comparison as a command
(cd web && npm run typecheck)     # UI types
```

| Package | What is covered |
| --- | --- |
| `domain` | Canonical JSON and digests (byte-compatible with the original), JavaScript number formatting, the privacy field guard, response interpretation. |
| `engine` | Full S0→S4 path and stage traces; identity carried through A/E/C; reproducible identities; refusal to re-decompose; rejection of invalid input before any state exists (unknown option/item, bad subject, prohibited context key, oversized input); no scalar career quantity; Cloud107 semantic boundary; authorization (no grant, missing scope, wrong subject, expired grant, exhausted budget) with nothing executed on denial; registry allowlist; pathway support, statuses and explanations; only the user decides; re-mapping keeps decisions; corrections are new records; model boundary (no provider, proposal-only records, metadata, output sanitising, never evidence); non-destructive versioning and tamper detection; append-only persistence; uncertainty flags and merge. |
| `api` | Every action over HTTP; refusals returned as rejections; session saved and restored with identical identities; reset; catalog; research endpoint; UI served. |
| `research` | **Parity:** the four experiments are re-run and every measurement, plus the deterministic signal identities, is compared with `research/results/experiments.json` and `experiments.md` generated by the original TypeScript code. |

## Manual test (UI)

Exercised end to end in Chrome at a phone viewport (390×844) against
`cmd/career107`:

- **App (client design):** registration → home overview → live test through
  all 19 items with Save & Continue (matrix, choices and free text) → results
  dossier with archetype, strengths and "% Matched" pathways → pathway detail
  with reasoning → recording a decision → syllabus lists every item →
  student portal shows the decision record → in-app Back → reload keeps
  everything.
- **Technical view:** capture, decompose, map, review, propose follow-up
  questions, correct a representation, run the research experiments, view the
  architecture screen; restart the server and confirm the session is restored.

## On a device

Install `dist/app-release.apk`, answer one item on the Capture tab, decompose
it, map pathways, then close the app fully and reopen it: the observation,
representation and pathway set must still be there.
